编排层

build.ts

  • build(options)：串起全部阶段，内联 filter / merge 逻辑。
  • 内部工具：checkUrlConflicts、resolveCover、copyDir、walkFiles、compileLess、dumpMiddle（调试落盘）。

core-api.ts

class CoreApiImpl implements CoreAPI {
  get root()   // 项目根
  get site()   // Site（config / pages / posts / assets）
  get theme()  // Theme（含 config）
  get helper() // HelperRegistry
}

build() 直接调用 initCorePlugins / loadThemePlugins / loadSitePlugins 完成初始化，并 new CoreApiImpl(...) 得到主题用 CoreAPI。

plugins/index.ts

  • initCorePlugins(site, cwd)：建 HelperRegistryImpl(site) 并注册核心 helper；建 generator/renderer/hooks；注册内置 markdown renderer；组装 scoped API（generator/hook/renderer/helper）；registerCoreGenerators(scoped.generator)；返回 { registries, scoped }。
  • loadPlugins(dir, scoped)：扫描目录，按文件名前缀 generator-|hook-|renderer-|helper- 经 jiti 动态 import，按前缀注入对应 scoped API。
  • scoped 类型定义在 types/api.ts：GeneratorAPI / HookAPI / RendererAPI / HelperAPI；内部编排类型 Registries。

领域模型

site.ts / collection.ts

  • SiteImpl(config)：持有 collections: Map、_assets、_config（不含 theme）；pages 为所有集合扁平化；posts 从 posts（+ renderDraft 时的 drafts）聚合。
  • CollectionImpl(name, config, pages)：getPages(sorted?) 按 sortBy(date/title) 与 sortOrder 排序。

assets.ts

  • scanAssets({contentRoot, assetsDirAbs, pages})：文章专属目录（与页面源文件同名目录）→ 专属 Asset；assetsDir → 全局 Asset；其余 → stray。
  • resolveAssetRef(ref, page, ctx)：外部/锚点原样；/assets/ 校验；相对路径先专属目录后全局；未命中 null。

markdown.ts

  • renderMarkdown(raw, page, ctx)：remark-parse → gfm → math → rehype(allowDangerousHtml) → raw → slug → toc 收集 → 资源解析 → mermaid → katex → shiki → stringify。
  • 资源解析经 ctx.assets.resolve(ref, page)；shiki 高亮器模块级单例；config.markdown 控制 highlight/katex/mermaid/clientHighlight。

theme/index.ts + theme/render.ts

  • resolveThemeDir（index.ts）：themes/<name> → node_modules/<name>（向上查找）。
  • loadTheme（index.ts）：esbuild bundle 入口为 ESM（preact 系列与 @hulog/core external），动态 import，合并 loadThemeConfig 到 theme.config。
  • renderPage（render.ts）：选布局（page.layout → default → page），preact-render-to-string 输出，前缀 <!DOCTYPE html>\n。
