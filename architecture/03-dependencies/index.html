插件加载与优先级

flowchart TD
  A["initCorePlugins(site, cwd)"] --> A1["HelperRegistryImpl(site) + registerCoreHelpers"]
  A --> A2["GeneratorRegistryImpl"]
  A --> A3["RendererRegistryImpl + register('markdown')"]
  A --> A4["initHooks()"]
  A --> A5["组装 scoped API：generator/hook/renderer/helper"]
  A5 --> A6["registerCoreGenerators(scoped.generator) → home / archive / taxonomy"]
  A6 --> B["loadThemePlugins(scoped, themes/&lt;theme&gt;/plugins)"]
  B --> C["loadSitePlugins(scoped, &lt;pluginsDir&gt;)"]
  C --> D["Registries + scoped API 就绪"]
  • 注册表为 Map，同名 register 覆盖（后注册者胜出）。
  • 加载顺序：内置 < 主题插件 < 站点插件。
  • 内置 generator 用 core: 前缀（core:home 等），与站点插件（如 home）不冲突。
  • 按文件名前缀注入 scoped API（互不越权）；无前缀文件忽略并警告；index.*（主题入口）跳过。

主题 bundle 的外部依赖

loadTheme（esbuild）将以下模块设为 external，与 core 进程共享同一实例：

flowchart LR
  bundle["theme bundle (ESM)"] -. external .-> preact["preact / jsx-runtime / hooks"]
  bundle -. external .-> prts["preact-render-to-string"]
  bundle -. external .-> core["@hulog/core"]

原因：preact 的 context/hooks 与 preact-render-to-string 需单实例互通；@hulog/core 供主题导入常量/工具且避免重复打包。
