我的主题介绍

发布日期: 2023-07-17更新日期: 2024-01-21

关于主题的介绍

前言

这篇文章算是我在开发过程中的一些总结与吐槽。

其实一开始我认为对于博客来说，应当注重于文章本身，而不是花哨的样式， 这也是我一开始打算写一个自己的主题的原因。 但后面我发现，过于单调的界面很难让我阅读下去， 于是我在文章中为特殊的元素，如：链接、表格、代码等地方使用了彩色。 这确实使得文章好看了一些，也促使我为主题添加更多东西。

写作

主题一开始就是基于 Markdown 渲染出的 HTML 文档进行开发， 因此对于普通的，用 Markdown 写出来的文章，主题的样式应该都是没什么问题的。

需要特别说明的是，在 Hexo 的文档标签插件中提到了许多写作格式（或许可以这样子称呼？）， 如：各种不同的引用、代码块以及图片视频等。 在我一开始开发主题时并没有看中这些方面的适配，但最近在对主题进行了一系列更新期间， 我发现了官方用于主题测试的一个示例， 于是我决定重新设计一些主题的的样式，并现在几乎能够适配示例中提到的各种写作风格。

除了那个diff样式，还有 Hexo 内置的带行号的代码高亮。 现在 gist 的 diff 样式强制使用亮色，Hexo 内置的代码高亮使用暗色。具体的介绍在后面有说。 HTML 标签一层又一层，真的难写，我本来就不会前端，越写越觉得写了个垃圾。

文章列表

主页文章列表以更新日期为顺序，展示了博客的所有文章，并提供访问文章的入口。

在 Hexo 中还有两种页面：标签页与分类页，这两种页面用于展示具有相同标签或者分类的文章。 在这两个页面中文章以发布时间作为排序顺序。

需要注意注意的是，在导航栏中指向的页面是用于展示博客拥有的标签或者分类，而不是展示文章的。

在官方示例中，我看到了几个我非常想要的样式：文章摘要、无标题文章、带封面文章1， 在主题中也实现了这些样式。

一般文章

摘要2其实就是文章前的一小段文字，比如这篇文章的摘要就是“关于主题的介绍”， 不过我在这里使用了样式，但在文章列表里只会显示文字。

在一开始设计的主页文章列表中，所有的文章都显示为一个标题加上一段截取的文章内容。 其实我挺不满意这样的实现，因为 Hexo 提供的辅助函数会把标题也截进去， 更难受的是一些数学公式会因为被截断导致不能渲染出来。 而我又不想自己写函数处理这些文字，于是我决定采用摘要作为显示方式。

想要使用摘要，只需在文章内这样写：

这一段文字是摘要。

<!-- more -->

这里开始是正文

在标签<!-- more -->上的内容会作为摘要显示在文章列表中，同时在文章内也会显示。 需要注意的是，文章 Front matter 区域里边可以设置变量excerpt， 这将文章列表中代替文章内的摘要进行显示，而文章内的摘要不变。

无标题文章

对于一篇没有标题文章，我认为它的用途就像是能在列表的一篇篇的文章中， 起到类似于文章内“引用”的作用，你可以写一小段简短的话，作为一个“引用”插入到文章列表中， 不过其实好像没什么必要。

此外，我选择实现这种布局另一个原因是为了适配一下出现无标题文章的情况。 由于评论功能使用到了文章标题，因此在没有标题的文章里不能使用评论功能（这是强制性的）。

只需要把文章标题，也就是title设为空字符串就能使用这种样式。

无分类文章

在 Hexo 的配置文件中，设置default_category: uncategorized， 并使用hexo new page uncategorized创建页面。

在“分类”页面即可看到“未分类”选项，即可查看所有无分类的文章。

带封面文章

一开始其实是想写个像幻灯片一样布局来着的， 不过我发现这些图片只能在首页显示3，或许更适合拿来作为文章封面。

值得一提的是，关于这个样式使用到的变量photos只是在这里提到过， 而且还没告诉你怎么用...

要为文章添加封面，可以有以下几种方式

全局封面

如果需要使用全局封面，需要在主题的配置文件中有如下配置：

covers:
  - "/covers/cover_1.jpg"
  - "/covers/cover_2.jpg"
  - "/covers/cover_3.jpg"

使用绝对路径4填写需要作为封面的图片文件路径。 并需要在文章内启用：使用cover: true表示此文章使用默认封面。 如果文章还使用了photos指定封面， 那么设置cover: true会将全局封面添加进文章的封面列表。

文章专有封面

所谓文章专有封面，其实就是使用文章资源文件夹下的图片作为封面。

这个方法需要在 Hexo 配置文件中启用post_asset_folder， 这会在创建文章时同时生成一个同名的文件夹， 把封面图片放入这个文件夹后，在 Front matter 区域添加：

photos:
  - pic1.jpg
  - pic2.jpg
  - pic3.jpg

这样就能使用封面了，如果有多个封面，则会随机选取。

这个方法还能使用绝对路径指定不在文章资源文件夹下的文件作为封面：

photos:
  - pic1.jpg
  - pic2.jpg
  - pic3.jpg
  - /img/pic4.jpg

使用/开始的文件路径，表示从网站根目录开始的绝对路径。

比如：网站地址为https://blog.example.com/， 则表示https://blog.example.com/img/pic4.jpg。 网站地址为https://example.com/blog/， 则表示https://example.com/blog/img/pic4.jpg。

外部图片

如果不希望在博客上存储封面，还可以从网络上获取。在 Front matter 区域添加：

photos:
  - https://via.placeholder.com/350x150.jpg

这样子就会从网络中获取封面。这个方式可以和之前的两种方式中的任意一个混合使用。

相册集

相册集可以看作是一种特殊的文章，它主要用于展示一些照片。 与普通的带封面的文章不同，相册集能够展示所有配置的照片， 而不是使用随机一张作为封面。 在使用photos配置好希望展示的图片后， 使用gallery: true启用相册集。

你也可以同时启用cover: true，这将会展示网站配置的所有默认封面。 此外，也能够在photo使用网络图片。

外部文章

外部文章指的是不在自己博客网站上的文章，也可以是一般的其他网页。 外部文章有两种：一种是带标题的，另一种是不带标题的。

带标题的在显示时会显示标题，而不带标题的则直接显示链接。 使用方式如下：

# 标题指定了就是带标题的，置空就是无标题的
title: ""
link: https://www.google.com

当点击时就会跳转到对应的网页，文章本身不会被访问（在考虑要不要实现访问的方式）。

置顶文章

这个功能其实本来不想写的，但就觉得主题里都塞那么多东西了，再加个文章置顶也无所谓， 于是就写了。

在文章 Front matter 区域添加如下字段即可：

pin: true

如果有多个置顶的文章，文章将会按照更新日期排序。

还在完善的文章

先说怎么用吧，在文章 Front matter 区域添加：

todo: true
todo_msg: ""

这样就行了，在文章列表中就能看到效果了。顺便解释一下： todo设置为true表示文章还未完善，todo_msg可以写一些原因，留空表示使用默认消息。

后面是关于这个功能实现的原因，不感兴趣的话就跳过吧。

这个功能的实现纯属是突发奇想。原因就是这篇文章写到一半时又想着实现置顶、 修改一些样式或者更改一些其他的功能。导致这篇文章修修改改了几次。 闲着无聊实现了文章入口的那个更新日期指示后，就想着加多一个样式， 然后就选了这个。

其实本来想着按照更新日期来决定样式的，最近更新的就显示绿色， 一段时间前更新的就显示橙色，长时间没有更新的就显示红色。

但转念一想，文章写好了就是写好了，顶多来点错别字修改， 一般不需要一直修改或者更新，那时间长了都变成橙色或者红色，就感觉怪怪的。 于是就想到了这样的情况：文章没有写完，但已经能够发布了，后面只需要慢慢更新就行。 这就是这个功能实现的由来了。实际上todo_msg还是在写这一小节时想出来的。

一些功能

知识共享授权

使用creativecommons字段配置授权。

creativecommons:
  license: "CC BY-NC-ND 4.0"
  link: "https://creativecommons.org/licenses/by-nc-nd/4.0/"
  description: "如无特殊说明，网站所有原创内容均采用#授权。"

description选项用于配置版权说明， 占位符#会被替换为license指定的授权协议名称， 并生成指向link配置的链接，

上述例子最终渲染的结果为：

<p>
  如无特殊说明，网站所有原创内容均采用
  <a href="https://creativecommons.org/licenses/by-nc-nd/4.0/">
    CC BY-NC-ND 4.0
  </a>
  授权。
</p>

代码高亮

使用主题提供的代码高亮

  1. 使用hexo-renderer-markdown-it 进行 markdown 文件渲染。

  2. 在_config.yaml中配置hexo-renderer-markdown-it 选项

  3. 在主题的配置文件中启用代码高亮

    hljs:
  enable: true
  # highlight.js CDN
  js: "https://cdn.jsdelivr.net/gh/highlightjs/cdn-release@11.9.0/build/highlight.min.js"
  # choose from https://github.com/highlightjs/highlight.js/tree/main/src/styles
  css:
    light: "css/github.min.css"
    dark: "css/github-dark.min.css"

主题配置中，js 和 CSS 资源可使用 CDN 或者本地资源 （上面的参考配置中，CSS 使用的即本地资源）。

使用 Hexo 内置的代码高亮

目前主题对 Hexo 内置代码高亮的样式尚未实现， 仅支持使用 highlght.js 在浏览器进行渲染。 禁用 Hexo 内置高亮请参考：https://hexo.io/docs/syntax-highlight.html#Disabled。

如果需要使用 Hexo 内置的代码高亮，需要启用 Hexo 配置中的这两个选项：

注：这是旧版本的 Hexo 开启内置高亮的方式。

highlight:
  enable: true
  hljs: true

还需要注意的一点是，如果同时启用了主题的高亮与 Hexo 内置的高亮， 那么将会优先使用 Hexo 内置的代码高亮样式。

搜索

搜索功能可能还会继续完善。

搜索功能在主题的 README.md 中似乎说完了，不过还是在这里再一遍。

目前主题提供两种方式：关键字搜索以及正则搜索。

关键字搜索

对于关键字搜索来说，可以使用查询规则。

语法
  • key1 + key2将会搜索包含key1或者key2的文章，它们的并集作为搜索结果。
  • key1 & key2将会搜索同时包含key1和key2的文章。
优先级

&符号优先级最高，其次是+，这意味着key1 + key2 & key3的结果为： 包含 key1 的文章，以及同时包含 key2 和 key3 的文章。

注：这个优先级规则可能会考虑更改，比如添加()来改变优先级。

正则搜索

目前正则搜索不支持标记5，在搜索过程中强制使用g标记进行搜索。

关于正则的语法请参考正则表达式。

评论

评论系统使用Gitalk，可以在主题的配置文件中选择开启， 在启用评论系统的情况下，还应该在文章中配置开启。

在配置文件中：

gitalk:
  enable: true

在文章中：

gitalk: true

只在配置文件中开启或者只在文章中开启将不会启用评论，此外没有标题的文章强制不启用。

外链

你可以在顶栏添加一些社交网页链接。就像这样子：

links:
  github:
    title: "Github"
    class: "bi bi-github"
    url: "https://github.com/HuzerOVO"

主题主要使用Bootstrap Icons，但主题也使用Font Awesome作为图标的补充。

比如在 Bootstrap icons 中，没有 BiliBili 的图标，但在 Font awesome 中有，于是就可以这样子：

links:
  bilibili:
    title: "哔哩哔哩"
    class: "fa-brands fa-bilibili"
    url: "https://www.bilibili.com"

需要说明的是，class字段根据 Bootstrap Icons 或者 Font Awesome 介绍的使用方式填写。

订阅链接

订阅链接可以使用hexo-generator-feed自动生成。

配置请参考：hexo-generator-feed

电子邮件

字段email可以设置你的电子邮件，如果设置了电子邮件地址， 那么在网页的 footer 区域会显示一个链接用于向你发送邮件。

“关于”页面

“关于”页面比较特殊，它几乎是套用了“文章”（post）的模板。 根据主题的页面配置指南， 应该存在这么一个文件：your-blog-root-dir/source/about/index.md。 这个文件可以像文章一样编辑，不过有这些不同： 你的excerpt会被作为个人的描述，并显示在头像下方， 其余内容则会像正常文章一样显示。

在关于页面，你可以使用gitalk和katex这两个变量。 不过不同于文章，你禁用了 Gitalk 后并不会显示“评论已禁用”这样子的提示框。

此外，不同与普通文章的是，你可以指定“关于”页面中的头像， 并在 Front matter 区域使用avatar指定头像文件名。

假设你此时文件夹结构如下：

your-blog-root-dir
+--scaffolds
...
+--source
   +--about
      +--index.md
      +--avatar.jpg

此时 index.md 文件的 Front matter 区域可以这样设置：

# 在关于页面，你可以使用一些文章布局的 Front matter 变量
# 比如 gitalk、katex
gitalk: false
katex: false

# 这些是专有的
avatar: avatar.jpg
avatar_size: normal

对于变量avatar_size，主题内置了 3 个预设值：small、normal（这是默认值）以及large。 对应头像大小：64px，125px 和 256px。 此外你还可以设定一个数字指定头像大小，单位为px，如：

avatar_size: 120

需要注意的是，头像文件只能放在 about 文件夹里，并且不能指定多个头像。

此外，头像的长宽比应当是 1:1 的，否则显示会很怪。

Front matter 参考手册

这里列出主题使用到的，可能会影响文章布局的变量作为参考：

title: 我的主题介绍
date: 2023-07-17 12:00:00
updated: 2023-12-31 09:17:43
toc: true
katex: false
gitalk: true
#issue_id: 46 # 指定 issue 用作评论区
todo: true
todo_msg: 主题仍在开发中
#excerpt: 主题仍在持续开发中 =v= # 这个会覆盖文章内摘要
pin: true
cover: false
gallery: false
photos:
  - id=89645004_p0.png
categories:
  - [开发记录]
tags:
  - 主题
  - Hexo
# 这个作为外部文章引用
#link: https://huzerovo.github.io/2023/07/17/introduction-to-my-theme/

对于“关于”页面则有：

gitalk: false
#issue_id: 45
katex: false
avatar: avatar.jpg
avatar_size: normal

除了以上的变量，主题还用到了 Hexo 提供的一些内置变量， 比如path表示页面路径，content表示文章内容等。 不过这些变量并不影响文章布局，因此不一一列出了。
