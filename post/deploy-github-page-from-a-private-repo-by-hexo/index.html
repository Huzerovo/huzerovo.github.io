使用 Hexo 从私有仓库部署 Github Page

发布日期: 2023-07-16更新日期: 2023-07-16

将博客源文件迁移至私有仓库

起因

在开始搭建博客时，为了能够自动部署 Github Page， 我参考Hexo 提供的教程创建了 Github Actions 进行自动构建。 但这导致源文件也要上传到仓库，然而我并不想把没写完的也传上去， 于是导致没写完的文章积压在本地。

不幸的是之前博客主要是存储在树莓派上，电脑上的是远古版本了。 在毕业后清理了一些在上面写的课程设计，不小心把博客也删掉了。 不过还好 折腾了几次树莓派的备份脚本，虽然折腾完就没用过多少次，幸好期间也没怎么开新的坑， 总算是没有完全丢失草稿。

于是就想着把博客源文件与 Github Page 仓库分离，把全部文件都上传到私有仓库里。

过程

其实在之前也想过把仓库变成私有的，但改了之后发现网站没了，去 Github Docs 看了才知道， 只有付费账户才能使用私有仓库构建 Github Page。

但我想保留原有的提交记录，于是我想着把当前存放源文件的分支上传到一个新的仓库， 在 Github Page 的仓库中创建 Actions，让它从我的私有仓库构建。 但转念一想：Github Actions 也没法访问我的私有仓库啊， 虽然能通过 Personal Token 可以做到， 但这玩意也不能放公开仓库用啊。

于是我又想：那我能不能在私有仓库构建好再推送过去。

本着能偷懒就不干活的精神，在搜索了一番后我发现， Hexo 教程中使用到的peaceiris/actions-gh-pages@v3本身就可以完成这个任务 （我还想着找不到就直接配置hexo deploy）。

于是参考peaceiris/actions-gh-pages进行了配置。

配置

  1. 在配置中的deploy_key其实就是 ssh 的私匙， 通过ssh-keygen生成一个就行：

    $ ssh-keygen -t rsa -b 4096 -f "hexo-deploy-action-key"

  2. 在私有仓库的Settings => Secrets and variables => Actions把私匙添加进去， 命个记得住的名（这个要用到的），在这里我用HEXO_DEPLOY_KEY命名。

  3. 在 Github Page 仓库中的Settings => Deploy keys把公匙添加进去。

  4. 配置actions-gh-pages，参考如下：

    # 前面的省略，与 Hexo 教程中的一样
- name: Deploy
  uses: peaceiris/actions-gh-pages@v3
  with:
    deploy_key: ${{ secrets.HEXO_DEPLOY_KEY }} # 这里的名字填你在步骤 2 中设置的名字
    external_repository: UserName/username.github.io # 你的 Github Page 仓库
    publish_branch: master # 在 Settings => Page 中设置的构建源分支
    publish_dir: ./public # Hexo _config.yml 中配置的 public_dir
    commit_message: "Deploy by Github Actions" # 随意

完事

没出错的话，当写完东西并推送到博客的源文件仓库后，就会开始构建。
