树莓派上运行的服务

发布日期: 2024-07-10更新日期: 2024-07-10

记录一下在树莓派上运行的一些服务

Nginx 服务器

我用域名1来访问树莓派上运行的所有服务，因此我搭建了 Nginx， 用来反代树莓派上所有服务。

Adguard Home DNS 解析服务

Github 仓库：https://github.com/AdguardTeam/AdguardHome

这个服务其实主要是用来解析树莓派的服务域名地址，广告过滤只是顺带的。 一开始是直接改 hosts 文件的，但这样要改所有会访问树莓派服务的设备的 hosts， 这导致 Android 和 ios 都没办法使用树莓派服务。后来是改树莓派上的 hosts 文件， 并配合 dnsmasq 进行解析，但是由于 dnsmasq 没办法用网页管理，于是就弃用了。

Aria2 下载服务

Aria2:https://aria2.github.io AriaNg: https://github.com/mayswind/AriaNg

Aria2 本身只有命令行界面，AriaNg 为其提供了 web GUI， 部署在树莓派上就能够通过网页远程管理 Aria2 了。

Aria2 用的频率其实不高，基本上只是用来下载一些需要在树莓派上使用的东西， 这样就不需要：开终端，wget 一下，然后进入漫长的等待，最后关终端。

Nextcloud 私有云盘

官网：https://nextcloud.com

云盘主要是用来自动上传文件，作为云端备份，比如这个博客的源文件就存在上面。 此外云盘有时会用 Collabora office 编辑一些文档，问就是懒得重启到 Windows 编辑。 但实际上用的很少，因为还在树莓派部署了 Collabora office 的内建服务器， 然而树莓派的性能有点不够用，能用就行，要啥自行车。

此外，云盘还被用来与 Aria2 配合，这样就能管理用 Aria2 下载的文件了。

Syncthing 文件同步服务

官网：https://syncthing.net

这个主要用来进行文件同步，但与 Nextcloud 有一些不同。

Nextcloud 在 Android 上有个奇奇怪怪的问题。 在 Linux 上，我能将本地的不同位置的文件夹，比如$HOME/Pictures/sync、$HOME/Videos/sync 同步到云端的一个文件夹内，比如sync/pictures、sync/videos。 但在 Android 上，我只能将云端的文件夹sync/pictures、sync/videos， 按照云端的结构同步到本地，如Android/media/.../sync/pictures、 Android/media/.../sync/videos。

这很不合理，因为我在 Android 也有Pictures/sync与Videos/sync， 而 Syncthing 能够满足这个需求。

为什么会在树莓派上部署呢？因为树莓派只是作为 syncthing 的中介人...

一些不常用的服务

Homeassistant 服务

官网：https://www.home-assistant.io

现已停用，原因：非常占内存，我的树莓派只有可怜的 2G。

Netdata 性能监控

官网：https://www.netdata.cloud

这个服务只是一时兴起部署的，几乎很少使用。 这个服务最大的共享就是让我发现 Nextcloud 的 PHP 后台真消耗性能，还有 HASS

Cups 打印机服务

有个打印机，用 cups 在局域网内共享，没啥好说的。 就是有时会找不到打印机，要重启一下服务

Cockpit 网页管理

官网：https://cockpit-project.org/

这个是 Redhat 赞助的一个项目，可以在网页上管理树莓派，比如更新软件，启动服务等。 但我还是更喜欢在终端中进行这些操作，偶尔会在手机上使用一下。

脚注

  1. 如 aria2.my.domain，adguard.my.domain，地址解析用到了自建的 DNS 服务。 ↩
